# Lichess API inventory

Snapshot taken on 11 November 2026 for Chess for Android. The live OpenAPI 3.1 bundle identifies itself as Lichess API **2.0.178**. It contains **190 HTTP method and path combinations across 176 paths**. The live bundle and the pinned documentation source agree on all method, path, operation ID, security, and server declarations. ### How authentication was classified

- The app requests `board:play`, `puzzle:read`, `puzzle:write`, `tournament:write`, `team:read`, and `team:write`. Lichess’s authorization-code flow with PKCE supports unregistered public clients. A new named permission requires a grant that includes it. [App OAuth configuration](../app/src/main/java/jwtc/android/chess/lichess/Auth.java) · [Lichess authentication documentation](https://lichess.org/api#description/authentication)
- Lichess’s OAuth middleware accepts any one of an operation’s alternative scopes. The incoming event stream accepts `challenge:read`, `bot:play`, or `board:play`. The direct create/accept/decline/cancel and computer-challenge operations accept `challenge:write`, `bot:play`, or `board:play`. The dedicated challenge list and challenge details use `challenge:read`. [Scope matching](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/modules/oauth/src/main/OAuthScope.scala) · [Event stream](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/Api.scala) · [Challenges](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/Challenge.scala) · [Computer challenge](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/Setup.scala)
- The OpenAPI declaration `security: []` specifies no OAuth requirement. An `OAuth2: []` requirement describes a bearer with no named scope, though several operations also have an anonymous branch. Some operations reject a bearer with insufficient scopes even when a request with no bearer can access public data. The server can return `X-OAuth-Scopes` and `X-Accepted-OAuth-Scopes` for its scoped routes. [Controller authentication wrappers](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/LilaController.scala) · [OAuth server](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/modules/oauth/src/main/OAuthServer.scala)
- The public API description and server code resolve declaration differences. Public profiles, user game and Arena exports, PGN import, and puzzle race results support unauthenticated access. Public team members, study exports, puzzle selection, and several broadcast reads also have an anonymous branch. Live anonymous probes returned HTTP 200 for the next puzzle and a public team members stream. - The spec lists no named scope for player notes and a user’s team list. Current server code requires `note:write` for both private note operations and `team:read` for `GET /api/team/of/{username}`. A live anonymous request to the team list returned HTTP 401. Challenge details have an anonymous controller branch, but it yields useful details only when the caller is identified as a participant. [Broadcast reference](https://lichess.org/api#tag/broadcasts) · [Broadcast tournaments](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/RelayTour.scala) · [Broadcast rounds](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/RelayRound.scala)

Team leadership and study ownership or contribution are independent of the OAuth grant. The server also defines `tournament:read` for website behavior. The published spec assigns it to no operation. [Public scope declarations](https://github.com/lichess-org/api/blob/313e6aac0d6005560ecb65525de2896f468b4a1b/doc/specs/lichess-api.yaml) · [Server scope definitions](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/modules/oauth/src/main/OAuthScope.scala) · [Tournament controller](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/Tournament.scala)
- `bot:play` grants the Bot API with a Bot account. A fresh account that has played no games can use it to convert irreversibly to a Bot account. `web:mod` is for authorized moderators, and the admin challenge-token endpoint checks the specific `ApiChallengeAdmin` permission. The signed-client scopes `web:mobile` and `web:polygon` belong to the official Lichess mobile app and Take Take Take. [Bot reference](https://lichess.org/api#tag/bot) · [Moderator token endpoint](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/app/controllers/OAuth.scala) · [Signed clients](https://github.com/lichess-org/lila/blob/9f8dd5df253455cd4890db27e6952b06e071b7e0/modules/oauth/src/main/OAuthSignedClient.scala)
- The Board API supports human play with normal accounts. For seeks, the documented time controls are rapid, classical, and correspondence. Blitz is additionally available for direct challenges, games against the Lichess computer, and bulk pairings. Game eligibility and Lichess fair-play rules apply to play through the app. [Board API reference](https://lichess.org/api#tag/board) · [Lichess fair play](https://lichess.org/page/fair-play)

The source snapshot is the verification basis for the identified declaration differences. Live checks were limited to a few read-only anonymous requests.
